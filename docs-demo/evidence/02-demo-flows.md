# Demo Flows

Discovery date: 2026-05-19.

These are evidence-backed demo flow maps, not recording scripts. Do not build
real Playwright flows from these until a focused UI selector pass confirms the
visible controls, stable text, and authentication setup.

Status legend: verified, partial, simulated, estimated, conceptual, unsupported,
unknown.

## Flow 0: Recording Prerequisites

Status: verified for setup surfaces, partial for runtime-heavy steps.

Evidence:

- `README.md`
- `backend/app/config.py`
- `backend/.env.example`
- `frontend/src/api/client.ts`

Required setup:

1. Backend: `uvicorn app.main:app --reload --port 8000` from `backend`.
2. Frontend: `npm run dev` from `frontend`.
3. Local login: `/login`, password from `API_KEY` in `backend/.env`; default is
   `sk-mock-admin-key` in repo config examples.
4. Worker for queued jobs: README uses `celery -A app.worker.celery_app worker --loglevel=INFO --pool=threads --concurrency=2`.
5. Redis for queued remote import, external training, and compression jobs.

What can be recorded in browser:

- Login.
- Project list.
- Official demo sample tiles.
- Project workspace and pipeline tabs.

What requires API/CLI or external runtime:

- Worker/Redis startup.
- External training.
- Compression.
- Tokenizer/model downloads.
- Teacher model, judge model, local serve runtimes.

Real flow:

1. Open the project list page.
2. The dashboard requests `GET /api/demo-projects`.
3. The backend reads official sample folders from `backend/data/demo_samples`.
4. Click exactly one of the three official demo tiles.
5. The frontend posts `POST /api/demo-projects/{slug}`.
6. The backend creates or reuses a project and returns the project id.
7. The frontend navigates to `/project/{id}`.

Browser should show:

- Only these official demo choices: `support-faq`, `pii-detector`,
  `sentiment-classifier`.
- A created project and workspace.

API/CLI fallback:

- Directly call `POST /api/demo-projects/support-faq`.
- Directly call `POST /api/demo-projects/pii-detector`.
- Directly call `POST /api/demo-projects/sentiment-classifier`.

Do not claim:

- Any other demo template.
- A generic template gallery beyond the three folders above.

## Flow B: Common Seeded Project Inspection

Status: verified for backend seed behavior, partial for UI exposure.

Evidence:

- `backend/app/services/demo_project_service.py`
- `frontend/src/pages/ProjectPipelinePage.tsx`
- `frontend/src/components/data/IngestionPanel.tsx`
- `frontend/src/components/data/GoldSetPanel.tsx`
- `frontend/src/components/data/DatasetPrepPanel.tsx`

Real seed behavior:

1. Project is created active with `pipeline_stage=PipelineStage.TRAINING`.
2. The sample CSV is copied into project raw data.
3. One `RawDocument` is created per CSV row with `source="demo"` and accepted
   status.
4. `gold.jsonl` is imported into a legacy gold file and a locked approved
   gold-set version.
5. Prepared `train.jsonl`, `val.jsonl`, `test.jsonl`, and `manifest.json` are
   written.
6. TRAIN, VALIDATION, and TEST dataset records/versions are created.

Browser should show:

- Project details.
- Data tab with raw documents or samples.
- Gold set tab with seeded gold examples if exposed.
- Dataset prep tab with split/profile/adapter surfaces.
- Later pipeline tabs unlocked for inspection.

Requires API/CLI if UI is missing:

- Inspect project data directory generated by the seeder.
- Query dataset/gold APIs directly.

Open UI questions:

- Does the UI expose the prepared manifest and exact split counts clearly?
- Does starting at `PipelineStage.TRAINING` visually hide or compress earlier
  stages?

## Flow D: PII Detector Pipeline

Status: partial.

Evidence:

- `backend/data/demo_samples/pii-detector/manifest.json`
- `backend/data/demo_samples/pii-detector/pii_records.csv`
- `backend/data/demo_samples/pii-detector/gold.jsonl`
- `backend/app/services/synthetic_service.py`
- `backend/app/services/eval_task_handler_service.py`
- `frontend/src/components/data/SyntheticPanel.tsx`

Real sample facts:

- CSV has 61 rows with `text` and `entities_json`.
- Gold JSONL has 200 rows.
- Manifest task profile is `structured_extraction`.
- Manifest target profile is `vllm_server`.
- Manifest output schema uses `scoring_mode=span_set`.
- Entity types in manifest: email, phone, ssn, credit_card, person_name,
  street_address, date_of_birth, ip_address, api_key, bank_account.
- Seeded split count is expected from code to be 45 train, 8 val, 8 test.

Browser story:

1. Seed `pii-detector`.
2. Inspect raw text and structured `entities_json`.
3. Show the manifest-backed entity type list.
4. Show that this is a detector/extractor sample, not the same feature as
   cleaning redaction.
5. Show span synthetic generation only if teacher/fallback prerequisites are
   configured and clearly labeled.
6. Show structured extraction evaluation only after a model/prediction source is
   configured.

What requires API/CLI or runtime:

- Synthetic span generation without fallback requires teacher model API.
- Real PII extractor training requires external/simulated training setup.
- Structured extraction scorecard requires predictions or held-out model eval.

Viewer should see:

- Typed spans with offsets or structured entities, plus a clear distinction
  between detecting PII and masking/removing PII during cleaning.

Do not claim:

- The model masks or removes PII unless that path is separately implemented and
  demonstrated.

## Flow F: Bring Your Own Dataset

Status: partial.

Evidence:

Supported surfaces:

- Upload and remote import exist under ingestion.
- Dataset import sources include CSV/JSONL, Hugging Face, and Kaggle adapters.
- Mappers include text-only, Q&A passthrough, label-to-classification,
  chat-message passthrough, preference pair, RAG passthrough, BIO-to-spans, and
  key-value to structured mapping.
- Dataset import runs write accepted transformed rows to a synthetic dataset.

Browser story:

1. Start with a raw custom file or remote source.
2. Preview rows and select a mapper.
3. Inspect accepted/rejected rows.
4. Run import and explain where rows land.
5. Continue into dataset prep and training only for steps verified in that
   custom configuration.

Do not claim:

- A fully generic arbitrary data-to-trained-model pipeline without verifying the
  chosen mapper, runtime, and task profile.
