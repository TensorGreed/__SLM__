# SLM 101

## What Is An SLM?

An SLM, or small language model, is a language model designed to be smaller, cheaper, faster, or easier to deploy than a large general-purpose model. "Small" is relative: it can mean fewer parameters, lower memory use, smaller context, narrower task scope, or a model tuned for a specific deployment target.

## Why Smaller Models Matter

- Lower serving cost.
- Lower latency.
- Easier on-device or private deployment.
- Better control for narrow tasks.
- Smaller blast radius when paired with strong evaluation and monitoring.

## Vocabulary

- LLM: a large general-purpose language model.
- SLM: a smaller model, often focused on a narrower task or deployment target.
- Fine-tuned model: a base model updated on task-specific examples.
- Adapter: a smaller set of learned weights or task mapping layered onto a base model.
- Dataset: examples used for training, validation, testing, or evaluation.
- Gold set: trusted examples used to judge quality.
- Synthetic data: generated examples used to augment or stress-test training/evaluation.

## Typical SLM Lifecycle

1. Define the task.
2. Collect or import data.
3. Inspect and clean data.
4. Create or import gold examples.
5. Generate or curate more examples if needed.
6. Prepare train/validation/test splits.
7. Select a base model and tokenizer.
8. Configure and run training.
9. Evaluate against gold data and gates.
10. Compress/export if needed.
11. Test the model in a real usage path.
12. Monitor and improve.
