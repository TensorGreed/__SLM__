# SLM 101 Narration Draft

Status: conceptual only.

Today we are going to set a foundation for small language model demos.

An SLM is a small language model. Small does not mean simple, and it does not mean weak. It means the model is designed to be practical for a narrower job, a smaller device, a lower latency target, or a tighter budget than a large general-purpose model.

A large language model is often useful when the task is broad and open-ended. A small language model becomes interesting when the job is more specific. Maybe we want a support assistant that answers from a known set of product tickets. Maybe we want a compact classifier that runs on a mobile CPU. Maybe we want a structured extractor that emits a specific JSON shape and can be evaluated strictly.

The important trade is focus. A smaller model can be cheaper to run, faster to serve, easier to deploy privately, and easier to reason about. But it needs a clear task, good data, and honest evaluation.

Let us separate a few terms.

The base model is the starting point. Fine-tuning is the process of adapting that model with examples. An adapter is a lightweight way to adapt behavior or map data for a task. A dataset is the collection of examples we use. A gold set is the trusted set we use to judge whether the model is doing the right thing. Synthetic data is generated data that can add coverage, but it should not replace careful evaluation.

A typical SLM lifecycle starts with a task. Then we gather data, inspect it, clean it, create gold examples, prepare splits, choose a model and tokenizer, train, evaluate, compress or export if needed, and finally test the result in the place users will actually use it.

The later BrewSLM videos will map that lifecycle onto this repository. We will be careful about evidence. Some content will be conceptual. Some features will be verified in the code. Some paths may be simulated or runtime-dependent. The goal is to avoid a generic machine learning demo and instead show what this tool actually does.
